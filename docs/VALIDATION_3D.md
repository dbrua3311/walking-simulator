# 과거 3D 사족보행 검증 (0.2.0)

사전 발 경로·16유전자 방식의 과거 기록이다. 현재 무작위 신경망의 보행 성공 근거가 아니며 현재 앱에서 이 파일을 재개하지 않는다. 현재 검증은 VALIDATION_LOCOMOTION.md를 따른다.

2026-11-07, Asia/Seoul. 사용자가 다리 끌기를 지적하고 3D·다리당 3관절을 선택한 뒤 실행한 결과다. 이전 2D 기록과 다른 평가 조건이므로 두 거리 수치를 성능 비교하지 않는다.

## 구현·자동 검증

- Rapier 3D: 13개 강체, 4×3개 회전 관절, 유한 토크 모터, 중력·지면 마찰·좌우 넘어짐.
- Three.js: 커버·센서·모터 하우징·기계 링크·고무 발, 회전 카메라, 상세·전체 보기, 선두 자동 관찰.
- 발 들기/이동/착지와 실제 지면 지지·미끄러짐을 구분하는 16변수 보행 제어·유전 알고리즘.
- Vitest **48개 통과**: 자유 낙하, 3축 모터 교정, 역기구학, 실제 접촉·12초 보행, 끌기·낮은 자세·높은 미끄러짐·한 발 지지 거절, 좌우 넘어짐, 시드 재현, 엘리트 보존, 정지 상태, 3D 파일 복원·다음 세대 일치.
- TypeScript 검사·프로덕션 빌드 통과.
- 실제 Chromium E2E **4개 통과**: 전체 보기 드래그·부모 확정, 자동 정지·재개와 상태 보존, JSON/CSV·손상 파일, 모바일.
- 최종 E2E 정지 조작→반영 **204ms**. 다른 최종 후보 실행에서는 80ms·262ms였다. 헤드리스 소프트웨어 WebGL에서 측정했으며 기존 200ms 목표를 매번 만족한 것은 아니다. 현재 브라우저 회귀 한도는 500ms이고 추가 최적화 대상으로 남긴다.
- Canvas 전용 DOM과 React 안내·선택 DOM을 분리해 개체 수 변경 후 화면이 사라지는 문제를 고쳤다. WASM 준비 전 시작 명령도 보존한다.

관절 solver 수렴이 낮을 때 어깨 목표와 실제 각도가 크게 어긋난 문제가 있었다. solver 12회·내부 PGS 4회, 고정 dt=1/120초로 조정한 뒤 어깨·엉덩이·무릎 각각의 **0.1rad 명령이 실제 약 0.1rad 변화**를 만드는 회귀 시험을 통과했다. 지면 마찰이 있는 상태의 속도 피드포워드는 접지 발 진동을 유발해 최종 제어에서 제거했다. 현재는 토크 제한이 있는 암시적 위치 모터와 목표 변화 속도 제한을 사용한다. 몸통에 전진 힘이나 자세 고정 힘을 가하지 않는다.

## 범위와 한계

특정 상용 로봇의 정확한 디지털 트윈, 실제 근육·힘줄 모델, 실물 로봇 검증 결과는 아니다. 로봇 내부 자기 충돌은 현재 비활성화되어 있다. 모터 일은 실제 motor impulse를 읽은 값이 아닌 보조 추정치다.

이 결과는 한 시드·10세대의 실제 관찰이다. 다른 시드의 수렴이나 장시간 성능을 보장하지 않는다. 더 무거운 3D 물리 때문에 높은 배속 설정을 항상 달성하지 못하며 화면에 실측 배속을 표시한다. 기존 Ubuntu·기존 aple·race-simulator는 수정하지 않고 소스·의존성은 별도 파티션, 캐시·브라우저·원본·산출물은 USB에 유지했다.

파일 형식 v2는 13강체 quaternion 상태와 12관절을 포함한다. v1 2D 파일은 현재 실험을 보존하면서 명시적으로 거절한다.
